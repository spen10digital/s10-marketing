# Runbook: M1.1 first deploy (dev AWS account + Vercel)

⛔ Every step that touches AWS, Vercel or GitHub settings is an **owner action** (CLAUDE.md rule 5). Claude Code prepares and reviews `cdk diff`; it does not deploy.

## Prerequisites (owner, one-time — 05 §8)
1. AWS Organization with `s10-marketing-dev` and `s10-marketing-prod` accounts, and IAM Identity Center with a `Developer` permission set for dev.
2. A local SSO profile: `aws configure sso --profile s10-dev` (region `us-east-1`).
3. GitHub repository created (D1, default `s10-marketing`, private), with push protection for secrets.
4. Vercel **Pro** team. Note its **team slug** (Team Settings → General → URL).

## 1. Vercel project
1. Import the GitHub repo as project **`s10-marketing`**. Set **Root Directory** to `apps/web` (framework Next.js; `apps/web/vercel.json` sets the install/build commands and region `iad1`).
2. Team Settings → Security → **OIDC Federation: issuer mode "Team"** (issuer `https://oidc.vercel.com/<team-slug>`).
3. Don't add env vars yet; they need the role ARNs from step 2.

## 2. AWS dev account
1. Sign in: `aws sso login --profile s10-dev` then `$env:AWS_PROFILE = "s10-dev"`.
2. Bootstrap once: `pnpm --filter @s10/infra exec cdk bootstrap aws://<dev-account-id>/us-east-1`.
3. Review the diff:
   `pnpm --filter @s10/infra exec cdk diff --all --context env=dev --context vercelTeam=<team-slug> --context githubRepo=<owner>/<repo> --context alertEmail=<you@example.com>`
4. Deploy (owner): the same command with `deploy --all` instead of `diff --all`.
5. Confirm the SNS email subscription from the inbox.
6. Copy the ARN of role `s10-marketing-dev-web-runtime` (IAM console).

## 3. Vercel environment variables (not secrets)
| Name | Preview + Development | Production |
|---|---|---|
| `APP_ENV` | `dev` | `prod` (after the prod account is deployed) |
| `AWS_ROLE_ARN` | `s10-marketing-dev-web-runtime` ARN | `s10-marketing-prod-web-runtime` ARN |

Never add `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`.

## 4. GitHub
Create environments `dev` and `prod` with required reviewer = owner. Set variables:
- `AWS_DEV_DIFF_ROLE_ARN` = `s10-marketing-dev-github-diff` role ARN
- `AWS_DEPLOY_ROLE_ARN` (environment variable on `dev`) = `s10-marketing-dev-github-deploy` role ARN
- `OPS_ALERT_EMAIL`

## 5. Verify
Push a branch (e.g. `develop`) → Vercel preview deploy. Open it:
- `/api/health` returns `{ ok: true, version: "<sha>" }`.
- `/dashboard` shows environment `dev`, publishing **Disabled** and Meta Graph `v26.0`. Those values come from Parameter Store, which proves the OIDC role works.

## Recurring cost created by this milestone
Vercel Pro (about $20/month per member) and the KMS customer managed key (about $1/month). Everything else is free tier or pay-per-use at idle (S3, SQS, SNS, Parameter Store standard, Budgets, Cost Anomaly Detection). Set a Vercel spend limit.

## Rollback
Vercel: Instant Rollback, or remove the project. AWS: `cdk destroy` of the dev stacks (owner). The KMS key is retained by design (30-day deletion window if removed manually); the dev media bucket is destroyed only if it's empty.
