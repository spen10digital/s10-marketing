# Runbook: M1.3 AI Studio on dev

Every step below changes AWS or the dev database, so each needs the owner's go-ahead (CLAUDE.md rule 5). Use the SSO profile: `aws sso login --profile s10-dev`, then `$env:AWS_PROFILE = "s10-dev"`.

## 1. Enable the models (owner, console)
1. Bedrock console → **us-east-2** → Model access: request access to **Claude Sonnet 5.5** and **Claude Haiku 5.5**.
2. Bedrock → Cross-region inference: confirm the US profile IDs. The code expects `us.anthropic.claude-sonnet-5-5` and `us.anthropic.claude-haiku-5-5` (`infra/lib/env-config.ts`). If they differ, change them there and in `packages/core/src/ai/pricing.ts`.
3. Note which **destination regions** the US profiles list. The web role allows us-east-1, us-east-2 and us-west-2 (`US_INFERENCE_REGIONS`); add any other listed region.

## 2. Check the organization SCP (owner)
The org SCP only allows regional services in us-east-2 (ADR 0013). A `us.` inference profile sends requests to other US regions, and an SCP that blocks those regions blocks the call. After deploying (step 3), run one call:

```powershell
pnpm eval:ai --env dev --case rewrite
```

- Works → nothing to do.
- `AI isn’t available in this environment yet` / AccessDenied → the SCP needs a narrow exception allowing `bedrock:InvokeModel` and `bedrock:InvokeModelWithResponseStream` in the profile's destination regions (recommended), or switch to in-region model IDs if Bedrock offers them for these models.

## 3. Deploy the stack changes (owner approval)
```powershell
pnpm infra:diff
```
Expected changes:
- **Core:** three new parameters: `ai-model-generate`, `ai-model-fast`, `ai-default-monthly-budget-usd` (`10`).
- **VercelAccess:** the web role gains `bedrock:InvokeModel`/`InvokeModelWithResponseStream` on the two inference profiles (and their foundation models only via those profiles), plus `cloudwatch:PutMetricData` limited to the `S10Marketing/AI` namespace.

Then, from `infra/`:
```powershell
npx cdk deploy S10Marketing-dev-Core S10Marketing-dev-VercelAccess --exclusively --context env=dev --context alertEmail=<owner email>
```

## 4. Migrate the dev database (owner approval)
```powershell
pnpm db:migrate --aws --env dev
```
Applies `0002_content_ai` (content, posts, AI generations, usage, entitlements; RLS forced).

## 5. Check it on the `develop` alias
1. Brand page → **Brand Voice assistant** → *Draft from website*: the proposal appears next to the saved version; *Use this draft in the editor*, then *Save new version* creates a normal version.
2. *Tune*: accept one suggestion, dismiss another; *Try it* writes sample posts.
3. **Studio** → write posts: drafts stream in; *Shorten* rewrites with Haiku; *Save draft* adds it to Recent drafts.
4. CloudWatch → Metrics → `S10Marketing/AI` shows tokens and cost.
5. The header shows this month's spend against the $10 budget.

## Operations
- **Change one org's limits** (until billing exists):
  ```sql
  insert into public.org_entitlements (org_id, ai_monthly_budget_micros, ai_daily_calls, web_fetch_daily)
  values ('<org id>', 25000000, 200, 40)
  on conflict (org_id) do update set ai_monthly_budget_micros = excluded.ai_monthly_budget_micros,
    ai_daily_calls = excluded.ai_daily_calls, web_fetch_daily = excluded.web_fetch_daily, updated_at = now();
  ```
  Run as `app_owner` (the app itself can't write this table).
- **Change the default budget:** `env-config.ts` → `ai.defaultMonthlyBudgetUsd`, then deploy Core.
- **Change a model:** update `env-config.ts` and `pricing.ts`, deploy Core and VercelAccess, run `pnpm eval:ai`.
- **Local development without AWS:** `AI_PROVIDER=fake` in `apps/web/.env.local` (refused outside `APP_ENV=local`).
